**蓄水池抽样**（reservoir sampling）是一类算法：从长度未知、或只能顺序读一遍的数据流里，均匀抽出固定个数的样本，且**不把整份数据先装进内存**。

算法题里最常见的是「池子大小为 1」：最终只要一个均匀随机元素。LeetCode [382. 链表随机节点](https://leetcode.cn/problems/linked-list-random-node/) 用的就是这一版。

## 1. 要解决什么问题

给定一串数据（数组、链表、文件、网络流……），记长度为 $n$（可以事先不知道）：

- 想均匀随机选出 $k$ 个互不相同的元素（每个大小为 $k$ 的子集概率相同）；
- $n$ 可能很大，或根本不知道；
- 往往只能从左到右扫一遍，不能按下标随机跳。

若 $n$ 已知且能随机访问，直接「洗牌取前 $k$ 个」或「随机下标」就够了。蓄水池针对的是：**$n$ 未知 / 只能顺序读 / 额外空间要跟 $k$ 走、不能跟 $n$ 走**。

## 2. 池大小为 1（最简版）

目标：最终留下一个元素，每个位置被留下的概率都是 $\frac{1}{n}$。

做法：边读边维护当前结果 `res` 和已见个数 $i$。

- 第 $1$ 个元素：必选，`res = a_1`
- 第 $i$ 个元素：以 $\frac{1}{i}$ 的概率把 `res` 换成它；否则保持原 `res`

```js
/**
 * 从可迭代序列中均匀抽 1 个元素（池大小 = 1）
 * @param {Iterable<any>} stream
 */
function sampleOne(stream) {
  let res
  let i = 0
  for (const x of stream) {
    i++
    // 以 1/i 的概率选中当前元素
    if (Math.random() < 1 / i) res = x
  }
  if (i === 0) throw new Error('empty stream')
  return res
}

// 示例
sampleOne([10, 20, 30, 40]) // 每个数被返回的概率都是 1/4
```

链表版（只存头指针，每次 `getRandom` 扫一遍）同理：

```js
function getRandom(head) {
  let res = 0
  let i = 1
  let node = head
  while (node) {
    if (Math.random() < 1 / i) res = node.val
    node = node.next
    i++
  }
  return res
}
```

### 2.1. 为什么最后人人都是 $1/n$？

看第 $k$ 个元素 $a_k$ 最终留在 `res` 里的概率：

1. 走到它时，以 $\frac{1}{k}$ 被选上；
2. 后面第 $j=k+1,\ldots,n$ 步都不能把它换掉，每步「不换」的概率是 $1-\frac{1}{j}=\frac{j-1}{j}$。

于是：

$$
\frac{1}{k}\times\frac{k}{k+1}\times\frac{k+1}{k+2}\times\cdots\times\frac{n-1}{n}=\frac{1}{n}
$$

中间项全部约掉。对任意 $k$ 都得到 $\frac{1}{n}$，所以等概率。

用 $n=3$ 验一下：

- $a_1$：必选，再留下 $=\frac{1}{2}\times\frac{2}{3}=\frac{1}{3}$
- $a_2$：以 $\frac{1}{2}$ 选上，再留下 $=\frac{1}{2}\times\frac{2}{3}=\frac{1}{3}$
- $a_3$：以 $\frac{1}{3}$ 选上 $=\frac{1}{3}$

注意：$a_1$ 选上是 $100\%$，但「最终留下」才是 $\frac{1}{3}$；被换掉会分散在后面多轮，不是一次性只按 $\frac{1}{3}$ 换掉。

## 3. 池大小为 $k$（一般版）

目标：留下 $k$ 个元素，每个大小为 $k$ 的子集概率相同（等价于每个元素入选概率为 $\frac{k}{n}$，且组合均匀）。

经典 Algorithm R：

1. 前 $k$ 个元素直接放进池子 `reservoir[0..k-1]`；
2. 从第 $i=k+1$ 个元素起：以 $\frac{k}{i}$ 的概率把它放进池子，并**等概率替换池里某一个位置**；否则跳过。

```js
/**
 * 从可迭代序列中均匀抽 k 个元素（不放回）
 * @param {Iterable<any>} stream
 * @param {number} k
 * @returns {any[]}
 */
function sampleK(stream, k) {
  const reservoir = []
  let i = 0
  for (const x of stream) {
    i++
    if (reservoir.length < k) {
      reservoir.push(x)
      continue
    }
    // 以 k/i 的概率替换池中一个随机位置
    if (Math.random() < k / i) {
      const j = Math.floor(Math.random() * k)
      reservoir[j] = x
    }
  }
  if (reservoir.length < k) {
    throw new Error(`stream shorter than k=${k}`)
  }
  return reservoir
}

// 示例：从 1..100 抽 5 个
sampleK(Array.from({ length: 100 }, (_, i) => i + 1), 5)
```

直观理解（和 $k=1$ 同一套思想）：

- 第 $i$ 个元素「进池」概率是 $\frac{k}{i}$；
- 进池后占池中某一格的概率是 $\frac{1}{k}$，合起来「占某一固定槽位」是 $\frac{1}{i}$；
- 再乘上后面各步不被挤掉的概率，最终每个元素入选概率为 $\frac{k}{n}$。

$k=1$ 时，$\frac{k}{i}=\frac{1}{i}$，且池里只有一个槽，就退化成上一节。

## 4. 复杂度和适用边界

| | 池大小 $1$ | 池大小 $k$ |
| --- | --- | --- |
| 时间 | 扫一遍 $O(n)$ | 扫一遍 $O(n)$ |
| 额外空间 | $O(1)$ | $O(k)$ |
| 需要预先知道 $n$？ | 否 | 否 |
| 需要随机下标访问？ | 否 | 否 |

适合：链表、日志流、大文件顺序读、面试里的「长度未知如何均匀随机」。

不适合当第一选择的情况：$n$ 很小且已知、又能随机访问——直接 `arr[Math.floor(Math.random() * n)]` 或洗牌更简单。

## 5. 和「先数长度再取模」的对比

```js
// 需要两遍，或先把数据装进数组
function sampleOneNaive(arr) {
  return arr[Math.floor(Math.random() * arr.length)]
}
```

| | 先 `len` / 先装数组 | 蓄水池 |
| --- | --- | --- |
| 遍数 | 往往 2 遍，或先 $O(n)$ 空间 | 1 遍 |
| 长度未知的流 | 难 / 不行 | 可以 |
| 额外空间 | 常 $O(n)$ | $O(k)$ |

所以题解注释出现「蓄水池抽样」，通常是在说：**在不能（或不想）预知长度、也不能 $O(n)$ 拷贝的前提下，用 $\frac{k}{i}$ 边读边换，保证均匀。**

## 6. 一句话

**蓄水池抽样 = 固定大小的样本池 + 读到第 $i$ 个元素时按 $\frac{k}{i}$ 决定是否换进池子；** 不依赖预先知道的 $n$，扫完后样本对已见过的全体仍是均匀的。
